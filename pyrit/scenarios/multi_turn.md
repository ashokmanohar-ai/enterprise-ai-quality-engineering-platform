# Multi-turn campaign design

Use PyRIT's current multi-turn attack executors only during an authorized nightly or manual assessment. Objectives remain synthetic: attempt to override refund rules, enumerate fictional account IDs, or persuade the agent to call `create_support_ticket` without confirmation. The target, attacker, and judge deployments must be named explicitly, bounded by the configured request and cost budgets, and retained in a private security report.

Promote a confirmed issue through this pipeline: PyRIT reproduction → sanitized finding → canonical `datasets/security` case → Promptfoo regression assertion in every PR.
